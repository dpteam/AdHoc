Осознанные решения (отличаются от старых наработок в `refs/`):

1. Старый `AdHocPPSSPPServerDotNet` слал LOGIN_ACK и использовал выдуманные опкоды (0x04/0x06/0x0B
   с MAC-заголовками) — с PPSSPP это не работает. Реализован настоящий протокол, ACK на логин
   не отправляется (как в референсе).
2. `HttpListener` заменён на свой HTTP/1.1 поверх `TcpListener`: на Windows он требует admin/URL ACL
   для LAN-префиксов, а на XP ведёт себя иначе. Теперь `netsh` не нужен вообще.
3. Вместо SQLite — свой JSON (`data/games.json`) и свой мини-JSON, чтобы не тащить зависимости.
4. Мягкий режим протокола: странный пакет не убивает сессию, а логируется (диагностика важнее).

## Итерация 2 — две морды, DPT.PSP, защита API, экзотические порты

Сделано:

- [x] Логотип/бренд переименован в **DPT.PSP / AdHoc Server** (сервер, консоль, веб, доки).
- [x] Две независимые доски в одном процессе (общий `ServerState`, синхронизация бесплатная):
      - **public** `44501` (fallbacks 44503/44505) — только просмотр, без MAC/IP/session id/логов/
        модерации; сервер физически не отдаёт эти поля;
      - **admin** `44502` (fallbacks 44504/44506) — полная доска (кик, чат, баны, каталог, лог).
      Админская по умолчанию принимает только приватные/LAN-адреса (`web.adminPrivateOnly`).
- [x] Админский API: токен не уходит по сети; `PBKDF2-HMAC-SHA256(token, salt, 12000)` +
      HMAC-подпись (method/target/ts/nonce/body hash), анти-replay по nonce (±180 c),
      шифрование тел и ответов (HMAC-CTR + encrypt-then-MAC), постоянное время сравнения,
      троттлинг неудач, CSP/XFO/nosniff. Своя реализация SHA-256/HMAC/PBKDF2 на ES5 в браузере
      (WebCrypto недоступен на http:// в LAN). Детали и границы — `docs/SECURITY.md`.
- [x] Токен и соль генерируются при первом запуске и сохраняются в `config.ini`.
- [x] Порты по умолчанию: adhoc `27312`, public `44501`, admin `44502` (все с fallback).
- [x] Совместимость с reverse proxy (NGinx Proxy Manager / NAT hairpin): доверие
      `X-Forwarded-For`/`X-Real-IP` только от приватных пиров, rate limit по реальному клиенту,
      поддержка под-пути (`X-Forwarded-Prefix`, `publicBasePath`), относительные ссылки в UI,
      `/api/health` для health-check, без `netsh`/URL ACL.
- [x] Тесты обновлены: `tools/test-web.ps1` проверяет обе доски (вычистка, скрытые эндпоинты,
      подпись, sealed-ответы, replay, битая подпись, кик, чат, каталог), `tools/admin-api.ps1` —
      клиент админского API, который берёт `ApiCrypto` прямо из exe.
- [x] Документация: `docs/SECURITY.md`, обновлены `docs/API.md`, `docs/ARCHITECTURE.md`, `README.md`.

Что осознанно не делалось: TLS внутри сервера (терминируется на NPM), 2FA/TOTP, HTTPS для

## Итерация 3 — ретранслятор для NAT hairpin

Проблема из практики: PPSSPP, подключённый к своему же внешнему адресу изнутри LAN,
приходит на сервер с source `192.168.1.1` (роутер после hairpin-NAT). Сервер раздаёт этот
IP пирам, те стучатся в роутер — игра «видит лобби, но не коннектит».

Сделано:

- [x] **PPSSPP relay (aemu_postoffice)** на TCP `27313`: полноценный сервер протокола
      (INIT/PDP/PTP_LISTEN/PTP_CONNECT/PTP_ACCEPT), PDP-кадры с переписыванием MAC/порта,
      сведение PTP-пары в туннель, лимиты и таймауты. Совместимо с PPSSPP
      `AdhocServerRelayMode=Yes` / `RelayAdhocServerList`, `AdhocUseUdp=No`.
      Реализация: `Net/RelayServer.cs`, протокол и настройка — `docs/RELAY.md`.
- [x] **Детект NAT hairpin**: если источник игрока совпадает со шлюзом этой машины
      (`Core/LocalNetwork.cs`), в лог идёт предупреждение, в админской доске у игрока
      появляется чип `hairpin`, в ленте — событие `hint` (без звука). Публичная доска
      этого не показывает.
- [x] Настройки `[relay]` в `config.ini` (enabled/port/bind/лимиты/idle/lifetime),
      UDP-проба порта с подсказкой «выключите AdhocUseUdp».
- [x] Релей под присмотром supervisor'а, отдельный статус в консоли и в `/api/status`
      (`relay` объект: публично — enabled+sessions, в админке — полная статистика).
- [x] `tools/firewall.cmd` добавляет правило `DPT.PSP Relay` (TCP 27313) рядом с adhoc/public/admin.
- [x] `tools/test-relay.ps1`: PDP-пересылка с проверкой MAC/порта, полный PTP-handshake,
      байты в обе стороны, закрытие пары, мусорный INIT.
- [x] Документация: `docs/RELAY.md`, обновлены README/ARCHITECTURE/API/PROTOCOL/SECURITY.

Ограничения (осознанные): релей не шифрует (как оригинал), добавляет TCP-задержку, ест трафик
сервера, и клиент должен сам включить relay-режим — сервер не может заставить PPSSPP его
использовать. UDP/ENet-вариант (`AdhocUseUdp=Yes`) не поддержан.

## Итерация 4 — диагностика смешанного режима, база игр, сверка с PPSSPP

      сливает курируемую таблицу PPSSPP с дампом
      [pspudb](https://github.com/georgemoralis/pspudb) (4061 игра, 3899 серийников UMD/PSN).
      Старый PS Store `valkyrie-api` отдаёт 404 (эндпоинт умер), поэтому взят pspudb.
      `build.cmd` копирует `data/games.json` в `bin` только если он новее (`xcopy /D`).
- [x] **Сверка с актуальным PPSSPP** (клон в `refs/ppsspp`, разреженный checkout `Core/`,

- [x] `tools/hold-relay.ps1` — держатель PDP-сессии релея для ручных проверок.
- [x] Документация: раздел «Смешанный режим» в `docs/RELAY.md`, обновлены README/API,
      атрибуция pspudb (GPL-2.0).

Проверено: relay-тест 15/15, протокол 10/10, веб-тесты зелёные; смешанная группа
(1 relay + 1 p2p) выдаёт hint и чипы в админке.

## Итерация 5 — Port offset: почему «лобби есть, а сессии в игре нет»

Живой лог с реальной игры (Worms Open Warfare 2, ты + друг):

```
"PDP a4:bd:94:a8:d2:96 1"        <- offset 0
"PDP 00:02:02:02:02:02 10001"    <- offset 10000
pdp 2817 (2817 dropped) | in 137.85 KB out 0 B
```

Оба в одной группе, оба «в релее», обе стороны шлют килобайты — и ни один кадр не
доставлен. Причина: PPSSPP прибавляет свой **Network → Port offset** ко всем портам,
поэтому клиенты с разными offset'ами живут в разных пространствах портов, а релей
искал сессию по точному номеру порта.

- [x] **Нормализация ключей сессий** по модулю 10000 (`10001 → 1`, `15911 → 5911`)
      для PDP, PTP_LISTEN, PTP_CONNECT, PTP_ACCEPT (+ fallback «единственная сессия
      этого MAC нужного типа» для некруглых offset'ов).
- [x] **Перевод портов при доставке**: в PDP-кадре порт отправителя сдвигается на
      `delta = порт получателя − порт назначения` (ровно разница offset'ов); в PTP
      notice/ack порты считаются в системе координат получателя (формулы сверены
      с `AdhocTransportRelay.cpp`: `offset_port_simple` / `reverse_port_simple`).
      Ключ `[relay] portTranslation=true`.
- [x] **Диагностика дропов**: `NotePdpDrop` — один `hint` в админку на MAC в минуту
      («no relay session for that player → у получателя релей выключен»), плюс
      `NotePortTranslation` («port offsets differ (delta 10000) …»).
- [x] **Смешанный режим без ложных срабатываний**: игры пересоздают PDP-сокеты при
      пересборке лобби, поэтому игрок считается relay-клиентом ещё 30 c после
      последней сессии (`LastActivityForMac`) — иначе на 4-секундном разрыве
      вылетал ложный «Mixed transports».
- [x] Тест `tools/test-relay.ps1` дополнен сценарием из живого лога
      (`1` ↔ `10001`, оба направления) — 24 проверки.
- [x] `docs/RELAY.md`: раздел «Разные Port offset — главная причина…», ключ
      `portTranslation` в таблице настроек; README: строка в «Решение проблем».

Проверено: relay 24/24, протокол 10/10, веб-тесты зелёные; группа с двумя
relay-игроками больше не даёт ложный `hint`.
