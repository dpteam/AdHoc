# Протокол SceNetAdhocctl (PPSSPP / PRO Online)

Сервер полностью совместим с тем, что ожидает PPSSPP (`Core/HLE/proAdhocServer.cpp`).
Формат сверен с актуальным `master` PPSSPP (файлы `Core/HLE/proAdhoc.h`, `proAdhocServer.cpp`,
загружены 2026-11-02): набор опкодов и размеры структур не менялись с оригинального PRO Online.
Ниже — байтовый формат, поведение сервера и отличия от референсной реализации.

## Транспорт

- TCP, порт **27312** (настраивается).
- Все структуры **packed**, порядок байт — big-endian (network order) для `uint32` IP.
- Никакого шифрования/сжатия, никакого framing-заголовка: поток — это просто
  последовательность пакетов, длина определяется опкодом.
- IP-адрес, который сервер отдаёт пирам, — это адрес TCP-соединения (тот, что видит сервер),
  4 байта в network order. PPSSPP использует его для UDP-трафика между игроками.

## Опкоды

| Код | Имя | Направление | Длина |
|---|---|---|---|
| `0x00` | `PING` | C2S | 1 |
| `0x01` | `LOGIN` | C2S | 144 |
| `0x02` | `CONNECT` | C2S | 9 |
| `0x02` | `CONNECT` | S2C | 139 |
| `0x03` | `DISCONNECT` | C2S | 1 |
| `0x03` | `DISCONNECT` | S2C | 5 |
| `0x04` | `SCAN` | C2S | 1 |
| `0x04` | `SCAN` | S2C | 15 |
| `0x05` | `SCAN_COMPLETE` | S2C | 1 |
| `0x06` | `CONNECT_BSSID` | S2C | 7 |
| `0x07` | `CHAT` | C2S | 65 |
| `0x07` | `CHAT` | S2C | 193 |

Константы размеров: MAC 6, ник 128, имя группы 8, product code 9, сообщение 64.

## Пакеты

### C2S LOGIN — 144 байта

```
offset  size  field
0       1     opcode = 0x01
1       6     MAC клиента
7       128   ник (UTF-8, NUL-padded)
135     9     product code (ASCII A-Z 0-9, например ULUS10084)
```

Сервер **не отвечает** на LOGIN: клиент сразу переходит в состояние «в сети».
(Ответ-ACK — распространённая ошибка самодельных серверов, PPSSPP его не понимает.)

Валидация: MAC не `00:00:00:00:00:00` и не `FF:FF:FF:FF:FF:FF`, ник не пустой,
product code — `[A-Z0-9]{9}` (можно отключить `requireValidProductCode=false`).

### C2S CONNECT — 9 байт

```
0       1     opcode = 0x02
1       8     имя группы (ASCII A-Za-z0-9, NUL-padded)
```

Сервер:
1. Находит/создаёт группу в текущей игре.
2. Каждому существующему пиру отправляет `CONNECT` с данными новичка.
3. Новичку отправляет `CONNECT` с данными каждого пира.
4. Новичку отправляет `CONNECT_BSSID` (MAC основателя группы; если он первый — свой MAC).

Порядок важен: BSSID уходит последним, после пиров.

### C2S DISCONNECT — 1 байт

`0x03` — «выйти из группы» (не «закрыть TCP»). Пиры получают `DISCONNECT` с IP ушедшего,
пустая группа удаляется, сессия остаётся залогиненной и может подключиться к другой группе.

### C2S SCAN — 1 байт

`0x04`. Если клиент не в группе, сервер отдаёт по одному `SCAN` на каждую группу этой игры,
затем `SCAN_COMPLETE`. Если клиент уже в группе — референсный сервер его выкидывает;
мы логируем предупреждение и отвечаем пустым списком + `SCAN_COMPLETE` (мягкий режим).

### C2S CHAT — 65 байт

```
0       1     opcode = 0x07
1       64    текст (UTF-8, NUL-padded)
```

Рассылается всем пирам группы, кроме отправителя (`CHAT` S2C). Вне группы — игнорируется
с предупреждением в лог.

### C2S PING — 1 байт

`0x00`. Ничего не отправляется в ответ; обновляется `lastRecv` сессии.
PPSSPP пингует примерно каждые 2 секунды, поэтому `userTimeoutSec=25` безопасен.
Пинги не пишутся в лог на уровне `Debug` (только `Verbose`), чтобы не заливать файл.

### S2C CONNECT_BSSID — 7 байт

```
0       1     opcode = 0x06
1       6     MAC «хостa» группы (BSSID)
```

### S2C CONNECT — 139 байт

```
0       1     opcode = 0x02
1       128   ник пира
129     6     MAC пира
135     4     IP пира (network order)
```

### S2C DISCONNECT — 5 байт

```
0       1     opcode = 0x03
1       4     IP ушедшего
```

### S2C SCAN — 15 байт

```
0       1     opcode = 0x04
1       8     имя группы
9       6     MAC хоста группы
```

### S2C SCAN_COMPLETE — 1 байт

`0x05`.

### S2C CHAT — 193 байта

```
0       1     opcode = 0x07
1       64    текст
65      128   ник отправителя
```

## Диаграмма

```
PPSSPP                          Server
  |-- LOGIN (144) --------------->|   сохранение игры/ника/MAC
  |                               |
  |-- CONNECT("ABCD1234") ------->|   группа найдена/создана
  |<--------------- CONNECT_BSSID |   MAC основателя
  |                               |
  |        (второй игрок)
  |-- LOGIN --------------------->|
  |-- CONNECT("ABCD1234") ------->|
  |<-- CONNECT(первый игрок) -----|
  |<--------------- CONNECT_BSSID |   MAC первого игрока
  |        (первому игроку)
  |            CONNECT(второй) <--|
  |                               |
  |-- SCAN ---------------------->|
  |<-- SCAN("ABCD1234", host MAC)-|
  |<-- SCAN_COMPLETE -------------|
  |                               |
  |-- CHAT("hi") ---------------->|
  |            CHAT("hi", ник) <--|   всем в группе, кроме автора
  |                               |
  |-- PING (каждые ~2 c) -------->|   тишина в ответ
  |-- DISCONNECT ---------------->|   выход из группы
```

## Отличия от референса (осознанные)

| Ситуация | PPSSPP PRO Online | DPT.Agent |
|---|---|---|
| неизвестный опкод | разрыв сессии | пропуск 1 байта + warn (можно включить строгий режим) |
| `CONNECT` без `LOGIN` | падение/игнор | warn, пакет игнорируется |
| `CONNECT` в другую группу без выхода | разрыв | авто-выход из старой группы, затем вход в новую |
| `SCAN` из группы | разрыв | пустой ответ + `SCAN_COMPLETE` |
| `CHAT` вне группы | разрыв | warn, игнор |
| дубль MAC | warn | warn + событие в UI; опционально кик (`kickDuplicateMac`) |
| IP-дубликат (NAT) | разрешён | разрешён, лимит `maxUsersPerIp` |
| таймаут | 15 c | 25 c (настраивается) |

## Логирование протокола

`logging.protocolTrace=true` и `logging.level=Debug` включают строки вида:

```
22:36:18.756 [D] PROTO  <- 127.0.0.1 [edce5f59b0] 144B 01 02 00 ... |....ROOM1234|
22:36:18.756 [D] PROTO  LOGIN Kai mac=02:00:00:29:00:01 ip=127.0.0.1 game=ULUS10084 (Monster Hunter Freedom)
22:36:18.756 [D] PROTO  group "ROOM1234" created in ULUS10084
22:36:18.756 [D] PROTO  -> 127.0.0.1 [edce5f59b0] S2C CONNECT_BSSID 02:00:00:29:00:01
```

Ошибки протокола (неизвестный опкод, неверный логин, переполнение) логируются на `Warn`
с hex-дампом — именно для разбора «почему не коннектится».

## Проверка вручную

```powershell
powershell -File tools\test-client.ps1
```

Скрипт поднимает три TCP-клиента, проходит LOGIN → CONNECT → SCAN → CHAT → DISCONNECT
и проверяет все ответы сервера, включая BSSID и crosslink.

## Ретранслятор игрового трафика (отдельный порт)

Помимо control-протокола на 27312 сервер умеет PPSSPP-релей (`aemu_postoffice`) на **TCP 27313**:
клиенты подключаются наружу, сервер сводит их в туннель и пересылает игровые байты.
Это спасает от NAT hairpin, CGNAT и «двух игроков за одним роутером», когда прямой UDP
между пирами невозможен.

Протокол релея (INIT 24 байта, PDP-кадры 14+size, PTP-handshake, лимиты и настройка
PPSSPP) описан отдельно: [RELAY.md](RELAY.md). Он не пересекается с `SceNetAdhocctl`:
control-порт только знакомит игроков, релей только носит байты.
