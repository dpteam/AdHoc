# Безопасность

Коротко: две разные морды на разных портах, у публичной нет ничего чувствительного,
админская — только LAN + подписанные и зашифрованные запросы. Ниже — что именно сделано,
от чего это защищает и где границы.

## Две доски

| | Public (`44501`) | Admin (`44502`) |
|---|---|---|
| Порт по умолчанию | `44501` (fallback 44503/44505) | `44502` (fallback 44504/44506) |
| Кому | интернет / reverse proxy | локальная сеть |
| Данные | ники, игры, группы, время, причины выхода | + MAC, IP, session id, байты, idle, лог протокола, баны |
| API | только `GET`, read-only | всё, но с подписью + шифрованием |
| Модерация | нет | кик, чат, правка каталога, reload |
| Скрытые эндпоинты | `/api/logs`, `/api/kick`, `/api/chat`, `/api/bans*`, `/api/reload`, `/api/auth`, `/admin.html` → `404` | — |

Публичная доска **физически не отдаёт** поля `mac`, `ip`, `idleSec`, `bytesIn/Out`, `pings`,
`session id`, `rawId` и события `error/ban/kick/chat`. Это не CSS-скрытие: их нет в JSON.

`web.adminPrivateOnly=true` (по умолчанию) заставляет админский порт отклонять соединения
с не-приватных адресов (`10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, `::1`).
Даже если случайно пробросить 44502 наружу — снаружи будет `403`.

## Админский API: токен, соль, подпись, шифрование

```
K     = PBKDF2-HMAC-SHA256(adminToken, adminSalt, 12000, 32)
kmac  = HMAC-SHA256(K, "dpt.mac.v1")
kenc  = HMAC-SHA256(K, "dpt.enc.v1")

canonical = METHOD \n path?query \n unixTs \n nonce \n hex(SHA256(wireBody))
X-Auth-Sig = hex(HMAC-SHA256(kmac, canonical))

request body  (опция) = base64( iv16 | HMAC-CTR(kenc, iv) XOR json | HMAC(kmac, iv|ct)[0..16] )
response body (опция) = тот же конверт, заголовок X-Enc-Resp: 1
```

Что это даёт:

- **Токен не уходит по сети.** Браузер вводит его один раз, выводит ключ локально
  (PBKDF2 + соль, 12 000 итераций) и хранит только в `localStorage`. На сервер едут подписи.
- **Соль на инсталляцию.** Одинаковые токены на разных серверах дают разные ключи;
  rainbow-таблицы по токену бесполезны. Соль генерируется при первом запуске в `config.ini`.
- **Целостность.** Подпись покрывает метод, путь, query, время и тело: подменить запрос
  «на лету» нельзя.
- **Anti-replay.** `nonce` (16 байт) кэшируется на 10 минут, повтор отклоняется (`401`);
  метка времени живёт ±180 с (часы браузера и сервера не обязаны совпадать — `/api/auth`
  отдаёт `ts`, клиент считает смещение).
- **Конфиденциальность.** Тело запроса и **любой** JSON-ответ админского API шифруются
  HMAC-SHA256 в режиме счётчика + encrypt-then-MAC (tag 16 байт). Пассивный сниффер в LAN
  увидит только base64-мусор. Заголовки и размеры остаются видны.
- **Сравнения без утечек по времени.** Подпись, тег и MAC сравниваются побайтово
  без раннего выхода.
- **Троттлинг.** 20 неудачных попыток за 5 минут с одного адреса → блок на 5 минут.

Всё это на чистом BCL (.NET 4.0): `HMACSHA256`, `SHA256`, `RandomNumberGenerator`.
На клиенте — свой ES5 SHA-256/HMAC/PBKDF2/CTR (`public/assets/js/crypto.js`), потому что
`crypto.subtle` недоступен на `http://` в локальной сети.

### Честные границы

- Это **не TLS**. Шифрование прикладного уровня защищает тела запросов/ответов и целостность,
  но не скрывает факт трафика, тайминги и заголовки; активный MITM может оборвать соединение
  (не подделать). Для публичной доски всё равно ставьте HTTPS на reverse proxy.
- Ключ живёт в браузере администратора. Зловред в браузере/расширение = полный доступ.
- Публичные данные публичны по определению: ники и названия игр видны всем.
- Протокол PPSSPP не шифруется (это ограничение клиента): сервер только знакомит игроков,
  дальше идёт прямой UDP между ними.

## Reverse proxy (Nginx Proxy Manager, nginx, NAT hairpin)

- Все клиенты приходят с одного адреса (NPM/роутер). Поэтому:
  - `X-Forwarded-For` / `X-Real-IP` учитываются **только** если непосредственный пир входит
    в `web.trustedProxies` (по умолчанию loopback + приватные сети);
  - из цепочки берётся первый **недоверенный** адрес справа налево — так спуфинг заголовка
    снаружи не помогает обойти лимиты;
  - rate limit (`web.requestsPerMinute`) считается по реальному клиенту, а не по NPM.
- Суб-путь (`https://host/adhoc/`): либо оставьте `publicBasePath=`, и путь срежется по
  `X-Forwarded-Prefix`, либо задайте `publicBasePath=/adhoc`. Ссылки в UI относительные,
  API-пути тоже — работать будет и на поддомене, и на под-пути.
- `/api/health` — удобно для health-check NPM.
- Никаких `netsh http add urlacl`: HTTP-сервер свой, слушает `TcpListener` на `0.0.0.0`.
  Достаточно разрешить `AdHocServer.exe` в фаерволе Windows.

Пример для Nginx Proxy Manager (Custom Location или Advanced):

```nginx
proxy_pass http://192.168.1.250:44501;
proxy_http_version 1.1;
proxy_set_header Host $host;                 # не обязателен, сервер не проверяет Host
proxy_set_header X-Real-IP $remote_addr;      # реальный клиент
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Prefix /adhoc;   # только если публикуете по под-пути
proxy_read_timeout 30s;
```

Замечание про NAT hairpin: при доступе из своей же LAN через внешний IP клиент может
выглядеть как LAN-адрес роутера, то есть как «доверенный прокси». Тогда подделанный
`X-Forwarded-For` теоретически позволит обойти rate limit (и только его — подпись и токен
это не затрагивает). В домашней сети это приемлемо; если критично — пробрасывайте порт
только на NPM и не открывайте `44501` напрямую.

## Прочая веб-защита

| Механизм | Где |
|---|---|
| CSP (`default-src 'self'`, `script-src 'self'`, без inline-скриптов) | каждый ответ |
| `X-Frame-Options: DENY`, `frame-ancestors 'none'` | каждый ответ |
| `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` | каждый ответ |
| `Cache-Control: no-store` для API, `no-cache` для HTML | ответы |
| Лимиты: тело 2 МБ, строка запроса 8 КБ, заголовки 64 КБ | `Web/HttpCore.cs` |
| 100 запросов на keep-alive соединение, 32 одновременных | `Web/WebServer.cs` |
| Rate limit по IP (скользящая минута) + 429 с `Retry-After` | `Web/WebServer.cs` |
| Защита от `..`/`\0`/выхода за `public/` | `ResolveSafe` |
| Админский HTML не отдаётся публичным портом | `ServeStatic` |
| Экранирование всего пользовательского текста в UI | `UI.esc` в `app.js` |
| Логи не содержат токен и тела запросов | `Log` |

## Токен

- Генерируется при первом запуске: 24 случайных байта (48 hex-символов) через
  `RNGCryptoServiceProvider`; соль — 16 байт.
- Лежит в `config.ini` (`web.adminToken`, `web.adminSalt`) и **печатается только в консоль**
  при старте (не в файл лога).
- Смена токена: впишите новый в `config.ini` и перезапустите сервер. Кнопка «Выйти из админки»
  в настройках чистит `localStorage` браузера.
- Пароль не передаётся и не хранится в БД — только ключ, выведенный из него.

## Чек-лист для публикации

1. Пробрасываете **только** `44501`. `44502` остаётся в LAN.
2. На NPM включите TLS (Let's Encrypt) и HSTS для публичного хоста.
3. Один раз выполните `tools\firewall.cmd` (UAC) — правила привязаны к exe и к приватным сетям.
4. Проверьте: `https://ваш-хост/api/logs` → `404`, `https://ваш-хост/api/status` без `"mac"`.
5. Админку открывайте по LAN-адресу: `http://192.168.x.x:44502/`, токен из `config.ini`.
6. `config.ini`: `adminPrivateOnly=true`, `adminEncrypt=true`, `trustProxyHeaders=true`,
   `trustedProxies` = подсеть NPM/роутера.
7. Не публикуйте `config.ini` и папку `logs/` (они и так в `.gitignore`).

## Ретранслятор

Релей (`Net/RelayServer.cs`) пересылает **открытый** игровой трафик, как и оригинальный
`aemu_postoffice`. Порт 27313 открыт для любых адресов (иначе внешние игроки не построят
туннель), аутентификации нет — идентификация по MAC из adhoc-логина, как в протоколе.
Лимиты: `relay.maxSessions`, `relay.maxPerIp`, idle/lifetime, максимальный PDP-кадр.
Если релей не нужен — `relay.enabled=false`, порт закрывается.

Hairpin-детект (источник = шлюз этой машины) только подсказывает в логе и админке включить
релей в PPSSPP; сам он трафик не перенаправляет.

## Что можно улучшить при желании

- HTTPS прямо в сервере (нужен самоподписанный сертификат + исключение в браузере) — не тащим,
  потому что NPM уже терминирует TLS.
- TOTP/2FA для админки — можно добавить без библиотек (RFC 6238 на HMAC-SHA1), если понадобится.
- Аудит-лог действий админа (кто кикнул) — сейчас пишется только событие `kick`.
